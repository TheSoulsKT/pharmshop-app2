# Сервер чата, админки и удалённых настроек (Cloudflare Workers + D1)

`worker.js` обслуживает чат поддержки, админ-панель и удалённые настройки приложения.

## Как обновить

1. Cloudflare → Workers & Pages → ваш воркер → **Edit code** → вставьте содержимое `worker.js` → **Deploy**.
2. Ничего больше делать не нужно: новые таблицы (`blocks`, `settings`) и колонки (`status`, `admin_read_ts`,
   `user_read_ts`) создаются сами при первом запросе. Старые чаты получат статус «Новый».
3. Старые версии приложения продолжают работать с новым воркером.

Переменные те же: `ADMIN_CODE` (обязательно), `BOT_TOKEN` и `CHAT_ID` (по желанию), привязка D1 с именем `DB`.

## Что появилось

| Возможность | Где в приложении |
|---|---|
| Статусы чатов «Новый / В работе / Решён», фильтры, «только непрочитанные», поиск по нику и номеру заказа | Админ-панель → Чаты поддержки |
| «✓ Доставлено / ✓✓ Прочитано» под сообщениями (в обе стороны) | Чат поддержки и админ-чат |
| Блокировка по устройству или IP | Админ-чат: кнопки «⛔ Устройство» и «⛔ IP»; список: Админ-панель → Блокировки |
| Пометка «⚠ с этого IP писали разные устройства» | Список чатов и админ-чат |
| Объявление на главном экране | Админ-панель → Объявление |
| Включение/выключение разделов, свои надписи и ссылки | Админ-панель → Разделы |
| Принудительное обновление | Админ-панель → Обновление |

Вход в админ-панель, как раньше: долгое нажатие на логотип на главном экране.

## Заметки

- Статус сам меняется на «В работе» при первом ответе админа и возвращается в «Новый», если пользователь
  пишет в уже «Решённый» чат.
- Пометка «разные устройства с одного IP» не доказательство: на мобильном интернете и в общих Wi-Fi
  у разных людей бывает один IP. Поэтому это только предупреждение, блокировка вручную.
- Блокировка по IP заденет всех, кто сидит за этим адресом. Приложение предупреждает об этом.
- Принудительное обновление работает только если приложение собрано на GitHub (есть `GITHUB_REPO`);
  в тестовой сборке оно не блокирует. Новая сборка с этой функцией должна выйти раньше, чем вы включите
  требование: старые версии о нём не знают и продолжат работать.
- Перед включением требования убедитесь, что релиз `build-N` уже опубликован на GitHub.
