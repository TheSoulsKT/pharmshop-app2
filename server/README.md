# Сервер чата, админки и удалённых настроек (Cloudflare Workers + D1)

`worker.js` обслуживает чат поддержки, админ-панель и удалённые настройки приложения.

## Как обновить

1. Cloudflare → Workers & Pages → ваш воркер → **Edit code** → вставьте содержимое `worker.js` → **Deploy**.
2. Ничего больше делать не нужно: новые таблицы (`blocks`, `settings`) и колонки (`status`, `admin_read_ts`,
   `user_read_ts`) создаются сами при первом запросе. Старые чаты получат статус «Новый».
3. Старые версии приложения продолжают работать с новым воркером.

Переменные те же: `ADMIN_CODE` (обязательно), `BOT_TOKEN` и `CHAT_ID` (по желанию), привязка D1 с именем `DB`.

## Что появилось

| Возможность | Где в приложении |
|---|---|
| Статусы чатов «Новый / В работе / Решён», фильтры, «только непрочитанные», поиск по нику и номеру заказа | Админ-панель → Чаты поддержки |
| «✓ Доставлено / ✓✓ Прочитано» под сообщениями (в обе стороны) | Чат поддержки и админ-чат |
| Блокировка по устройству или IP | Админ-чат: кнопки «⛔ Устройство» и «⛔ IP»; список: Админ-панель → Блокировки |
| Пометка «⚠ с этого IP писали разные устройства» | Список чатов и админ-чат |
| Объявление на главном экране | Админ-панель → Объявление |
| Включение/выключение разделов, свои надписи и ссылки | Админ-панель → Разделы |
| Принудительное обновление | Админ-панель → Обновление |

Вход в админ-панель, как раньше: долгое нажатие на логотип на главном экране.

## Заметки

- Статус сам меняется на «В работе» при первом ответе админа и возвращается в «Новый», если пользователь
  пишет в уже «Решённый» чат.
- Пометка «разные устройства с одного IP» не доказательство: на мобильном интернете и в общих Wi-Fi
  у разных людей бывает один IP. Поэтому это только предупреждение, блокировка вручную.
- Блокировка по IP заденет всех, кто сидит за этим адресом. Приложение предупреждает об этом.
- Принудительное обновление работает только если приложение собрано на GitHub (есть `GITHUB_REPO`);
  в тестовой сборке оно не блокирует. Новая сборка с этой функцией должна выйти раньше, чем вы включите
  требование: старые версии о нём не знают и продолжат работать.
- Перед включением требования убедитесь, что релиз `build-N` уже опубликован на GitHub.

## Безопасность (обновление)

### Ключ подписи приложения
Ключа в репозитории больше нет: сборка берёт его из секретов GitHub и **не запустится без них**.
В репозитории → Settings → Secrets and variables → Actions добавьте 4 секрета:
`KEYSTORE_B64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`.
Свой ключ можно создать так (потом `base64 -w0 my.keystore` → в `KEYSTORE_B64`):

    keytool -genkeypair -keystore my.keystore -storetype PKCS12 -alias pharmshop -keyalg RSA -keysize 4096 -validity 10950

Храните ключ и пароли вне репозитория. **Потеряете ключ — приложение нельзя будет обновить поверх установленного.**

⚠ Подпись сменилась, поэтому версия на старом ключе **не обновится** на новую: пользователям нужно один раз удалить
приложение и поставить заново (локальная история заказов и чат поддержки привязаны к устройству и пропадут).
Старый ключ остаётся в истории git — считайте его скомпрометированным и больше не используйте
(при желании историю можно вычистить через `git filter-repo`, но уже скачанные копии это не отзовёт).

### Проверка обновления
Сборка кладёт в релиз рядом с APK файл `.apk.sha256` и строку `SHA-256: …` в описание. Приложение сверяет сумму после
скачивания и не ставит файл, если она не совпала или её нет. Ссылка на APK должна вести на `github.com/<репозиторий>/releases/download/`.
Сумма защищает от повреждённой и подменённой по дороге загрузки; от захвата самого репозитория защищает только секретность ключа подписи.

### Вход в админ-панель
Теперь код вводится один раз: сервер выдаёт токен на 30 дней, приложение хранит его **зашифрованным** (Android Keystore) и шлёт только токен.
Токен сбрасывается при выходе из панели и при смене `ADMIN_CODE` в воркере. После обновления приложения администратору нужно один раз войти заново.
Старые версии приложения шлют код в каждом запросе, и воркер это пока принимает. Когда все обновятся, добавьте в воркер переменную
`LEGACY_ADMIN_CODE = off` — тогда код принимается только при входе.

### Лимиты чата
За 10 минут: не больше 20 сообщений и 5 фото с одного устройства, 60 сообщений с одного IP; не больше 5 новых обращений с одного IP в час;
тело запроса не больше 2 МБ. Числа меняются константами `RATE_*` в начале `worker.js`.

### Release-сборка
Теперь собирается `assembleRelease` с R8 (сжатие и обфускация). Файл `mapping.txt` сохраняется артефактом `R8-mapping` — он нужен, чтобы читать стектрейсы.
Если после включения R8 что-то ведёт себя странно, смотрите правила в `app/proguard-rules.pro`.

## Push-уведомления

Работают **без Firebase и Google-сервисов** (подходят и для телефонов без Google Play): `PollWorker` на WorkManager раз в 15–30 минут
(минимум, который Android разрешает для периодических задач) коротко опрашивает воркер и, если что-то произошло, показывает уведомление:

| Что | Когда |
|---|---|
| Поддержка ответила | есть непрочитанные ответы админа (`/api/chat/poll`; опрос ничего не помечает прочитанным) |
| Заказ выполнен / отменён | статус заказа сменился с момента, когда пользователь последний раз видел его на экране |
| Новое обращение (только админу) | в чатах появились непрочитанные сообщения (`/api/admin/poll`, нужна активная сессия админа) |

Пока приложение открыто, уведомления не показываются. Нажатие открывает нужный экран (чат, профиль, админ-панель).
Пользователь включает и выключает их в профиле («🔔 Уведомления»). На Android 13+ разрешение спрашивается при первом запуске.
Опрос чата идёт только у тех, кто хоть раз писал в поддержку.

Чтобы включить, достаточно задеплоить новый `worker.js` и выпустить новую версию приложения.

Ограничения: уведомление приходит с задержкой до ~30 минут, а на некоторых оболочках (Xiaomi, Huawei, Samsung с «экономией батареи»)
система сильнее откладывает фоновые задачи — пользователю может понадобиться разрешить приложению работу в фоне.
Если нужна мгновенная доставка — следующий шаг FCM (нужен проект Firebase и `google-services.json`) или UnifiedPush для устройств без Google.

## Структура кода приложения

`MainActivity.kt` теперь только хранит состояние и жизненный цикл. Экраны вынесены в файлы как расширения `MainActivity`
(логика не менялась):

| Файл | Что внутри |
|---|---|
| `Ui.kt` | анимации, виджеты (кнопки, чипы, поля), каркас экрана `screen()`, `backRow()` |
| `Home.kt` | главный экран и карточки меню |
| `AppUpdate.kt` | обновление приложения, удалённые настройки, обязательное обновление |
| `SupportChat.kt` | частые вопросы и чат поддержки |
| `AdminChats.kt` | вход админа, список чатов, чат с пользователем |
| `AdminSettings.kt` | объявление, разделы, принудительное обновление, блокировки |
| `BuyStars.kt`, `BuyPremium.kt` | покупка звёзд и Premium, оплата |
| `Profile.kt` | профиль и заказы |
| `OrderStatus.kt` | разбор статуса заказа (общий для экранов и уведомлений) |
| `Notifier.kt`, `PollWorker.kt` | уведомления и фоновый опрос |

## Мгновенные push (FCM)

Мгновенными становятся **сообщения чата**: пользователь → админу и админ → пользователю. Статусы заказов по-прежнему приходят фоновым опросом
(их ведёт сторонний сайт, и сигнала о смене статуса от него нет). Фоновый опрос остаётся запасным вариантом, повторов уведомлений не будет.
Работает на устройствах с сервисами Google; на остальных (Huawei без GMS и т.п.) уведомления приходят опросом.

Без шагов ниже ничего не ломается: сборка идёт как обычно, push просто не активируются.

1. **Проект Firebase.** [console.firebase.google.com](https://console.firebase.google.com) → Add project (Google Analytics можно отключить).
2. **Приложение Android.** В проекте → значок Android → имя пакета `ru.pharmshop.app` → скачайте `google-services.json` и положите в репозиторий как
   `app/google-services.json` (рядом с `app/build.gradle`). Этот файл не секретный, его можно коммитить.
3. **Ключ сервера.** Project settings → Service accounts → Generate new private key → скачается JSON.
   В Cloudflare → ваш воркер → Settings → Variables and Secrets → добавьте секрет `FCM_SERVICE_ACCOUNT` и вставьте в него **весь текст** этого JSON. Сам файл больше нигде не храните и не коммитьте.
4. Задеплойте новый `worker.js` и соберите приложение (push в `main`).

Проверка: установите приложение, напишите в поддержку, закройте приложение и ответьте из админ-панели с другого телефона. Уведомление должно прийти за секунды.
Для админа: войдите в админ-панель (токен FCM сам передастся серверу), закройте приложение и напишите в чат с другого устройства.

Заметки:
- Через серверы Google проходит текст уведомления (до 160 символов сообщения). Если это неприемлемо, оставьте FCM выключенным: опрос работает без Google.
- Тестовая сборка `PharmShop Test` (`ru.pharmshop.app.test`) использует другое имя пакета: для неё в Firebase нужно добавить ещё одно приложение и обновить `google-services.json`, иначе сборка из ветки test не пройдёт.
- Если ключ из шага 3 утёк, удалите его в Firebase (Service accounts → Manage → Keys) и создайте новый.
- Недействительные токены сервер удаляет сам. Если админ не вышел из панели на старом телефоне, push туда продолжат идти, пока токен жив; выход из панели отзывает его.
